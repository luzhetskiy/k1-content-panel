# Полнота данных строителей: график работы, логотип, запасная подпись

## Проблема

Проверка прода 10.09.2026 по двум жалобам («тизеры без полной инфы»,
«нет логотипа на странице строителя») вскрыла пять независимых дефектов.
Факты ниже — с прода, не предположения.

**1. Колонки выгрузки Яндекса не импортируются.** В файле есть «График»
(заполнен в 95% строк) и «Логотип» (78%), но `COLUMNS`
(`app/companies/import_xlsx.py:14`) про них не знает. Следствия: у всех 20
созданных сервисом тизеров на bolars-shop.ru поле `description` (режим
работы) пусто против 116 из 117 у заведённых руками; блок
`builder-line-time` на карточке строителя вырезается всегда.

**2. Логотип ищется скрейпингом вместо готового значения.** Комментарий в
`app/companies/logo.py:1` и `app/companies/builder.py:129` утверждает, что
колонки «Логотип» в выгрузке нет. Она есть. Скрейпер промахивается примерно
в 30% случаев (bolars.ru — 5 из 19, bolars-shop.ru — 9 из 20), и у каждой
промахнувшейся компании (rubkoff.ru, inwood.ru, skvlasov.ru, sip-lider.ru,
project-me.ru, akademik-stroy.ru) логотип в выгрузке присутствует.

**3. Перезаливка логотипа портит SVG.** `logo_filename`
(`app/companies/builder.py:28`) всегда даёт `.webp`, конвертации нет —
заливаются исходные байты. Из 36 перезалитых логотипов: 23 PNG, 2 JPEG,
9 SVG, настоящего WebP ноль. Сайт отдаёт их с `Content-Type: image/webp`;
растр браузер вытягивает сниффингом, SVG под чужим MIME не рисуется —
9 битых логотипов. Логотипы Яндекса приходят JPEG, то есть расширение
придётся чинить в любом случае.

**4. `data:`-заглушка принимается за логотип.** `_relocate_logo`
(`builder.py:142`) пропускает только пути, начинающиеся с `/`, поэтому
`data:image/svg+xml;utf8,<svg><rect fill='transparent'/></svg>` с
lazy-load-сайтов уезжает прямо в страницу — прозрачный прямоугольник
вместо логотипа (компании 280 и 312 на проде).

**5. Запасной подписи нет ни у одного сайта.** Когда логотипа нет,
`fill_builder_template` (`app/companies/template.py:58-70`) удаляет
`<img id="builder-logo">` и пишет название в `<span id="builder-logo-text">`.
Но в эталонных страницах этот span лежит **внутри HTML-комментария**, а
`_remove_comments` вырезает комментарии первым делом — значит `soup.find`
его не находит и подпись не появляется. Проверка всех 13 сайтов с
шаблоном: живого `builder-logo-text` нет **ни у одного**, у 9 он
закомментирован, у 4 отсутствует вовсе. Отсюда страница 338 на bolars.ru
(Рубкофф) — пустой блок без логотипа и без названия.

Дефект усугубляется петлёй: `sync_builder_reference`
(`app/companies/reference.py`) берёт эталоном уже собранную страницу, а
`fill_builder_template` при сборке один из двух элементов **удаляет**.
Какой элемент вырезали при сборке эталона — такого в шаблоне больше нет.

Сверх того из выгрузки не добирается ничего: 177 компаний из 5214 без
телефона, 1180 без email — эти пробелы остаются как есть.

## 1. Импорт xlsx: три новые колонки

```python
COLUMNS = {
    ...,
    "working_hours": "График",
    "logo_url": "Логотип",
    "phone_all": "Все телефоны",
}
```

`REQUIRED_KEYS` не меняется — новые колонки необязательны, файл без них
импортируется как раньше.

`ParsedRow` получает `working_hours: str = ""` и `logo_url: str = ""`.
Телефон — `phone_landline or phone_mobile or phone_all` (сейчас первые два),
«Все телефоны» как третий запасной источник; срез по первому сегменту до
`|` остаётся. `logo_url` — тоже первый сегмент до `|`: колонка «Фото»
хранит список через `|`, и хотя «Логотип» на разобранном файле всегда
одиночный, контракт источника один и тот же.

Диагностика неопознанных колонок в объём **не входит** — по решению
владельца импортируемый файл будет стандартизирован на стороне выгрузки.

### Модель и миграция

```python
class CompanyCandidate(Base):
    ...
    working_hours: Mapped[str] = mapped_column(String(300), default="")
    logo_url: Mapped[str] = mapped_column(String(500), default="")
```

Миграция Alembic: `add_column(company_candidates, working_hours)`,
`add_column(company_candidates, logo_url)`. Новых полей у `CompanyInfo` нет:
график живёт в `contacts[0]["working_hours"]` (шаблон уже умеет его читать,
`template.py:159`), логотип — в существующем `builder_logo_src`.

## 2. `CompanyInfo` из кандидата и обновление при пересборке

`_company_info_from_candidate` переезжает из `app/api/company_batches.py:142`
в новый модуль `app/companies/info.py` — её нужно звать и из билдера, а
импортировать API-модуль в Celery-задачу нельзя.

```python
def build_info_from_candidate(company: Company, candidate: CompanyCandidate) -> CompanyInfo:
    return CompanyInfo(company_id=company.id, **_fields_from_candidate(candidate))


def refresh_info_from_candidate(db: Session, company: Company) -> None:
    """Повторно берёт достоверные поля из кандидата. Нужна потому, что
    CompanyInfo заполняется один раз при создании партии: после доработки
    импорта у старых компаний в contacts нет working_hours, а в
    builder_logo_src — логотипа из выгрузки, и пересборка сама по себе их
    не подтянет."""
    if company.candidate_id is None:      # мигрированные из CLI — кандидата нет
        return
    candidate = db.get(CompanyCandidate, company.candidate_id)
    if candidate is None:
        return
    info = company.info
    for field, value in _fields_from_candidate(candidate).items():
        # Логотип из выгрузки перекрывает всё; если в выгрузке его нет —
        # оставляем уже найденный скрейпингом, иначе каждая пересборка
        # заново ходила бы на сайт компании за тем же файлом.
        if field == "builder_logo_src" and not value:
            continue
        setattr(info, field, value)
    db.commit()
```

`_fields_from_candidate` отдаёт `builder_name`, `city_name`, `address`,
`coordinates`, `contacts` и `builder_logo_src`. `city_prepositional` и
`builder_logo_alt` в неё не входят — у кандидата источника для них нет
(см. §6), и затирать их нельзя.

Вызов — первым шагом `CompanyBuilder.build()`, до `_scrape`.

В `contacts[0]` добавляется `"working_hours": candidate.working_hours`.

## 3. Логотип: порядок источников и верное расширение

Порядок по решению владельца: **выгрузка Яндекса → скрейпинг сайта →
запасная подпись названием**. Первый шаг делает §2 (`builder_logo_src`
приезжает из кандидата), второй — существующий `_find_logo`, который и так
срабатывает только при пустом `builder_logo_src`. Менять сам порядок в
`build()` не требуется.

Перезаливка переписывается целиком:

```python
_EXT_BY_CONTENT_TYPE = {
    "image/svg+xml": ".svg", "image/png": ".png", "image/jpeg": ".jpg",
    "image/webp": ".webp", "image/gif": ".gif",
}


def logo_filename(company_id: int, ext: str) -> str:
    return f"cp-company-{company_id}-logo{ext}"


def _relocate_logo(self, info: CompanyInfo) -> None:
    src = info.builder_logo_src
    # data:-URI — не логотип, а lazy-load-заглушка (прозрачный <svg>):
    # скачать её нельзя, а оставить как есть означает прозрачный
    # прямоугольник вместо логотипа на странице.
    if not src or src.startswith("/") or src.startswith("data:"):
        if src.startswith("data:"):
            info.builder_logo_src = ""
            self.db.commit()
        return
    ...
    ctype = response.headers.get("Content-Type", "").split(";")[0].strip().lower()
    ext = _EXT_BY_CONTENT_TYPE.get(ctype)
    if ext is None:
        logger.warning("логотип компании %s: неизвестный тип %r — пропускаю",
                       self.company.id, ctype)
        info.builder_logo_src = ""
        self.db.commit()
        return
    info.builder_logo_src = self.site_client.upload_file(
        response.content, logo_filename(self.company.id, ext), SERVICE_IMG_DIR)
```

Расширение определяется по `Content-Type` ответа, не по URL: у логотипов
Яндекса (`avatars.mds.yandex.net/.../XXXL`) расширения в пути нет вовсе.
Неизвестный тип — обнуляем и уходим на запасную подпись, а не заливаем
мусор.

Побочный эффект: файлы старой схемы (`cp-company-N-logo.webp`, 36 штук)
остаются в filemanager сайтов как осиротевшие. Это безвредно — чистка
вручную, вне объёма.

## 4. Скрейпер логотипа: фиксы и поиск

По решению владельца — и защитные фиксы, и расширение поиска.
`find_logo_url` перестаёт возвращать строку-URL: inline-`<svg>` возвращать
нечем, поэтому вводится результат с двумя вариантами.

```python
@dataclass(frozen=True)
class LogoCandidate:
    url: str = ""           # внешняя ссылка — качаем и перезаливаем
    svg_markup: str = ""    # inline <svg> из шапки — заливаем как .svg
```

Что меняется:

- **`data:`-URI отбрасывается** в `_find_img_in_scope` — как источник он
  бесполезен, а именно он сейчас побеждает на lazy-load-сайтах.
- **Ленивая загрузка**: кроме `src` проверяются `data-src`, `data-lazy`,
  `data-lazy-src`, `data-original`, `srcset`/`data-srcset` (первый URL
  списка). На `sip-lider.ru` настоящий логотип лежит в `data-lazy`, в `src`
  стоит `lazy.svg`.
- **Чёрный список переписывается.** Сейчас `_SKIP_SRC` режет
  `/wp-content/uploads/` — а на WordPress-сайтах именно там лежит настоящий
  логотип (skvlasov.ru: `/wp-content/uploads/2024/11/logo.png`). Вместо
  фильтра по пути — фильтр по контейнеру: пропускаем картинки внутри
  элементов, чьи `id`/`class` совпадают с
  `partner|client|brand|portfolio|gallery|slider`. Сигнал `logo|лого` в
  `src`/атрибутах остаётся обязательным, как сейчас.
- **Inline `<svg>`**: если `<img>` не нашёлся, ищем `<svg>` внутри
  элемента-кандидата на логотип (`_is_logo_candidate`) в шапке. Разметка
  сериализуется, при отсутствии добавляется `xmlns`. Это случай rubkoff.ru
  — логотип у него `<svg>` внутри `<a class="header__logo">`.
- **Cookie-заглушка Beget**: запросы через `requests.Session`; если ответ
  короче ~1 КБ и содержит `set_cookie` вместе с `beget`, ставим
  `beget=begetok` и повторяем запрос один раз. Так отвечает timesvai.ru —
  274 байта JavaScript вместо страницы.

`_relocate_logo` для `svg_markup` грузит `markup.encode("utf-8")` под
именем `cp-company-{id}-logo.svg`, минуя `requests.get`.

Чего скрейпер не научится и после этих правок: логотип, заданный
`background-image` в CSS. Так сделан inwood.ru — `<a class="head_logo">`
с текстом, спрятанным через `text-indent:-9999px`, и картинкой в правиле
`.head_logo{background:url(.../logo-top.png)}`; `<img>` на странице нет
вовсе. Парсить CSS ради этого не стоит — у inwood.ru, как и у остальных
промахов, логотип есть в выгрузке Яндекса, а она теперь первый источник.

Отдельно: содержимое `<noscript>` перепарсивать не требуется — bs4 с
`html.parser` разбирает его как обычные элементы, и `find_all("img")`
достаёт их уже сейчас (проверено).

## 5. Шаблон: прятать, а не удалять

Корень дефекта 5 — разрушающее заполнение. Оба элемента остаются в
разметке всегда, лишний скрывается:

```python
def _hide(tag) -> None:
    tag["hidden"] = ""
    if tag.name == "img" and tag.get("src"):
        # без src скрытая картинка не делает лишнего запроса, но сама
        # разметка доживает до следующей синхронизации эталона
        tag["data-src"] = tag["src"]
        del tag["src"]


if logo_src:
    if logo_img:
        logo_img["src"], logo_img["alt"] = logo_src, logo_alt
        del logo_img["hidden"]
    if logo_text_span:
        _set_text(logo_text_span, "")
        _hide(logo_text_span)
else:
    if logo_img:
        _hide(logo_img)
    if logo_text_span:
        _set_text(logo_text_span, name)
        del logo_text_span["hidden"]
```

`del tag["hidden"]` на элементе без атрибута — no-op у BeautifulSoup,
отдельная проверка не нужна.

### Контракт эталона

`_REQUIRED_MARKERS` в `app/companies/reference.py` дополняется
`builder-logo` и `builder-logo-text`, а `_missing_markers` начинает
**вырезать комментарии перед поиском** — ровно как это делает
`fill_builder_template`. Без этого закомментированный span считается
присутствующим, что и произошло на всех 13 сайтах.

Текст ошибки должен объяснять причину, а не только называть id:

> в эталонной странице нет обязательных элементов шаблона:
> builder-logo-text — если он есть, но закомментирован, комментарий нужно
> снять: сервис вырезает комментарии перед заполнением

После этого синхронизация 13 сайтов упадёт, пока эталоны не поправят, —
это осознанно: молчаливая потеря подписи хуже громкого отказа. Разовая
правка — в §7.

## 6. Мелочи, всплывшие попутно

**Пустой адрес роняет сборку невнятно.** Партия 11 (Тверь) целиком легла с
`создание тизера: HTTP 400: {"address":["Это поле не может быть пустым."]}`.
Проверка переезжает в `_create_teaser` до обращения к API:

```python
if not address:
    raise SiteAPIError(
        "у компании нет адреса — тизер без адреса сайт не принимает; "
        "заполните адрес у кандидата или исключите компанию из партии")
```

**`city_prepositional` не заполняется нигде** — отсюда «Картек-Строй в
рабочий посёлок Нахабино» и заголовок «Рубкофф — монтаж в Москва».
Детерминированного правила для русского предложного падежа нет
(Тверь → Твери, но Ярославль → Ярославле; «рабочий посёлок Нахабино» →
«рабочем посёлке Нахабино»), поэтому форму возвращает модель: в
`builder_text` добавляется пятый ключ ответа `city_prepositional`.

Ключ **необязательный**: `AI_TEXT_FIELDS` и проверка полноты ответа не
меняются, а `_apply_ai_fields` пишет его только если он пришёл. Не пришёл —
остаётся сегодняшний запас (`city_prepositional or city_name`,
`template.py:37`). Так старый промпт, уже сохранённый в БД, продолжает
работать.

Важно: `seed_prompts` идемпотентна и существующий промпт **не
перезаписывает**, поэтому правка `DEFAULT_PROMPTS` в коде на прод сама не
доедет — глобальный `builder_text` нужно обновить через админку промптов
(разовая работа, §7).

Заголовок страницы и `meta_description` в `_create_page` тоже переходят на
предложную форму.

**Двойной слэш в `remote_url`.** У сайтов с `base_url`, оканчивающимся на
`/`, выходит `https://stroybaza-tveri.ru//s/tverstroy-tver/` — в
`_create_page` и `_create_teaser` база берётся как
`self.site.base_url.rstrip("/")`.

## 7. Разовые работы на проде

Порядок важен — каждый следующий шаг опирается на предыдущий.

1. **Повторный импорт `builders_yandex_2026-07-10.xlsx`** через обычную
   загрузку в панели. Upsert по `site_key` (`app/companies/imports.py`)
   обновит все 5214 существующих кандидатов, добавив им `working_hours` и
   `logo_url`; новых строк не появится.
2. **Правка 13 эталонных страниц**: рядом с `<img id="builder-logo">`
   должен стоять живой (не закомментированный) `<span class="h2
   builder-logo-text" id="builder-logo-text">`. У 9 сайтов он уже есть в
   комментарии — достаточно снять комментарий; 4 эталона (51, 204, 106,
   61452) придётся дописать. Скрипт `execution/backend/
   fix_builder_reference_logo_text.py` по образцу
   `fix_article_image_collision.py`: тянет страницу через `SiteClient`,
   раскомментирует или вставляет span, PATCH-ит обратно. Затем
   «Проверить и синхронизировать» на каждом сайте.
3. **Обновление промпта `builder_text`** в админке — добавить
   `city_prepositional` в описание формата ответа.
4. **Обнуление залежавшихся логотипов**: у 64 компаний из партий
   `builder_logo_src` сбрасывается в `''`. Иначе пересборка не тронет ни 9
   битых SVG (путь начинается с `/`, `_relocate_logo` их пропускает), ни 2
   `data:`-заглушки. После сброса цепочка §3 переразрешает логотип с нуля.
5. **Пересборка 64 компаний** — существующим `POST /api/companies/{id}/retry`
   (он намеренно разрешён для `published` и обновляет страницу и тизер
   вместо создания дублей, `company_batches.py:300`). Ссылки и slug'и не
   меняются. Запускать партиями, а не все 64 разом: у воркера
   `concurrency=2`, каждая компания — это ещё один платный вызов RouterAI.

Шаг 5 стоит денег на RouterAI: тексты генерируются заново. Дешевле было бы
обновлять только разметку, но отдельного «пересобрать без текста» в сервисе
нет — заводить его ради разовой операции избыточно.

## Тесты

- `import_xlsx`: файл с «График»/«Логотип»/«Все телефоны» → поля в
  `ParsedRow`; файл без них → импорт проходит, поля пусты; телефон берётся
  из «Все телефоны», когда «Мобильные» и «Немобильные» пусты.
- `info.refresh_info_from_candidate`: подтягивает `working_hours` в
  `contacts[0]`; логотип из выгрузки перекрывает найденный скрейпингом;
  пустой логотип в выгрузке не затирает найденный; `candidate_id=None`
  (мигрированная из CLI) — no-op; `city_prepositional` не затирается.
- `_relocate_logo`: `data:`-URI → `builder_logo_src` обнуляется, запроса
  нет; `Content-Type: image/svg+xml` → имя файла `.svg`; `image/jpeg` →
  `.jpg`; неизвестный тип → обнуление без заливки; путь на `/` не трогается.
- `logo.find_logo_url`: `data-lazy` вместо `src`; `data:`-заглушка в `src`
  не побеждает реальный URL в `data-lazy`;
  логотип в `/wp-content/uploads/` находится; картинка внутри
  `class="partners"` игнорируется; inline `<svg>` в шапке → `svg_markup`;
  ответ-заглушка Beget → повтор с cookie.
- `template.fill_builder_template`: есть логотип → `img` заполнен, span
  скрыт и пуст; нет логотипа → span содержит название и видим, у `img`
  стоит `hidden` и нет `src`; **оба элемента присутствуют в выдаче в обоих
  случаях** (это и есть защита от петли эталона).
- `reference._missing_markers`: закомментированный `builder-logo-text`
  считается отсутствующим; живой — присутствующим.
- `_create_teaser`: пустой адрес → `SiteAPIError` с внятным текстом, запрос
  к API не уходит; `working_hours` уезжает в `description`.
- `builder_text`: ответ модели без `city_prepositional` не ломает сборку,
  с ним — поле проставляется.
