# Раздел «Метатеги категорий»

## Задача

Метатеги страниц категорий на сайтах сейчас шаблонные: title — голое название
(«Фанера»), description — общий текст «…и другие товары для отделки, ремонта и
строительства на Стройбазе!», keywords — снова название. H1 собирается шаблоном
сайта без склонения: «Купить Фанера выгодно».

Нужно писать title, h1, description, keywords и ai_keywords для каждой категории
каталога по статистике запросов Яндекс Wordstat и записывать их на сайт.

Требования владельца:

- **Регион** — анализ по конкретному городу проекта, город есть в тегах.
- **Склонение** — берётся та форма названия, которая частотнее в Wordstat. Если
  частотнее несклонённая, фраза строится так, чтобы читалась корректно
  («Фанера в Москве — купить…», а не «Купить фанера»).
- **Продающие фразы** — купить, цена и т.п., по статистике.
- **Цена в тегах не пишется.** Опция «добавить минимальную цену» отклонена
  владельцем 2026-09-16: цены переменные, ресурс на это не тратим.
- **Бренд** в конце title — остаётся.
- **keywords** — не больше 10.
- **ai_keywords** — отдельное поле сайта; туда генерятся фразы, которые могут
  цеплять LLM-поиск.
- Уже заполненные вручную метатеги **перезаписываются**; прежние значения
  сохраняются в панели.
- Теги пишутся на сайт **сразу**, без черновика в панели.
- Ручной правки тегов в панели **нет** — только просмотр и перегенерация
  (править руками — в админке сайта).

## Что проверено до проектирования (2026-09-16, stroybaza-moscow.ru)

### Wordstat API

- `POST https://searchapi.api.cloud.yandex.net/v2/wordstat/topRequests`,
  заголовок `Authorization: Api-Key <ключ>`. `folderId` в теле не понадобился —
  папка берётся из сервисного аккаунта ключа.
- Тело: `phrase`, `numPhrases` (1–2000, строкой), `regions` (список id строками),
  `devices`. Ответ: `totalCount`, `results[{phrase, count}]`,
  `associations[{phrase, count}]` (не больше 20). Числа приходят строками.
- Справочник регионов — `POST .../v2/wordstat/getRegionsTree` с пустым телом
  (не `regionsTree` — тот отвечает 404; ошибка найдена на живой проверке),
  дерево `{id, label, children}`. Москва = `213`, Москва и область = `1`.
- **Квота: 100 запросов в час, 10 в секунду.** Это главное ограничение всего
  дизайна.
- Счётчики `topRequests` — широкое соответствие: все словоформы, фраза входит в
  более длинные запросы. Форма фразы в выдаче **не** говорит, какая форма
  частотнее: в выдаче было «купить фанеру в москве», а точная проверка
  `"!купить !фанера +в !москве"` = 120 против `"!купить !фанеру +в !москве"` = 85.
  Склонение проверяется только отдельными запросами с операторами `!` и `""`.

Для фанеры по Москве: «фанера» 96 275, «фанера купить» 12 238, «фанера цена»
5 300; точные формы — «купить фанера» 678 против «купить фанеру» 234.

### API сайта (платформа одна для всех сайтов проекта)

Авторизация везде `Authorization: Token ...`, как у staticpages.

**Метатеги — `/api/v1/metatags/`** (список, POST, `/{id}/` — GET/PATCH):

- поля: `url` (обязательное, начинается и заканчивается `/`, ≤255), `title`
  (≤255), `h1` (≤255), `meta_keywords`, `meta_description`, `seo_text`,
  `ai_keywords`;
- пагинация `count/next`; **фильтр `?url=` игнорируется** — сопоставление с
  категорией по url делается на нашей стороне по полному списку;
- переопределение работает: у ГКЛ в метатеге задан h1 — он и стоит на странице;
- `title` подставляется **как есть**, бренд сайт не дописывает — « | {бренд}»
  добавляем сами.

**Категории — `/api/v1/catalog-categories/`**: 77 шт., по 50 на страницу,
`id, name, slug, published, parent, is_container, seo_text, updated…`. Дерево в
три уровня (12 корневых, 51 второго, 14 третьего). Ответ тяжёлый (~155 КБ на
страницу, seo_text внутри): первая попытка вернула обрезанное тело, повтор с
таймаутом 120 с — целое. Читать через `SiteClient._json` и с запасом по таймауту.
Фильтры `products-common` (`?category=`, `?search=`) сайт тоже игнорирует.

**Выбран API, а не sitemap.** В sitemap 934 каталожных url, из них категорий
только 70 — остальные ~860 это фильтр-страницы (`?tip-smesi=gruntovka&
proizvoditel=knauf`); ни названий, ни иерархии там нет. API даёт дерево и имена.

**Url категории по правилу:** корневая — `/catalog/{slug}/`, любая вложенная —
`/catalog/category/{slug непосредственного родителя}/{slug}/`. Сверено со всеми
70 категориями из sitemap, совпало. 7 категорий в sitemap отсутствуют — все 7
не опубликованы (живая проверка; первоначальная оценка «3 + 4 без страницы»
считала только первую страницу выдачи API). Sitemap используется
только для этой сверки — отсеять категории без живой страницы.

## Решение

### Подход

Факты и решения — кодом, тексты — LLM (RouterAI) по редактируемым промптам.
Отклонены: чистые шаблоны без LLM (однотипные description, нет осмысленных
ai_keywords) и LLM-агент с Wordstat как инструментом (непредсказуемый расход при
квоте 100/час).

### Данные

**Проект = существующая карточка сайта** (`sites`), отдельной сущности нет. Новые
поля сайта:

- `meta_enabled` — проект добавлен в раздел;
- `city` — «Москва»;
- `city_in` — «в Москве», «во Владимире» — вместе с предлогом (предлог
  зависит от слова); если при сохранении пусто — заполняет LLM, можно поправить
  руками;
- `wordstat_region_id` — подбирается по названию города из `regionsTree`, при
  неоднозначности выбирается из подсказок;
- `brand` — «Стройбаза».

**`category_meta`** — строка на категорию сайта:

- `site_id`, `remote_id` (id категории на сайте), `remote_parent_id`, `name`,
  `slug`, `url`, `skip_reason` (неопубликована / нет страницы / удалена на сайте);
- `seed_phrase`, `form_nominative`, `form_buy` («купить фанеру»), `form_price`
  («цена фанеры»);
- `chosen_form` (`nominative` | `declined`), частоты обеих форм, `total_count`,
  `low_demand`;
- `title`, `h1`, `meta_description`, `meta_keywords`, `ai_keywords`;
- `previous_json` — что было в метатеге сайта до первой нашей записи;
- `remote_metatag_id`;
- `status`: `new` (ещё не обрабатывалась) → `queued` → `in_work` → `done` |
  `failed`; `skipped` для отсеянных; `error_text`, `wait_until`, `started_at`,
  `updated_at`;
- `seed_source_name` — имя категории, по которому получена фраза: фраза
  перезапрашивается у LLM только при переименовании категории.

**`meta_run`** — запуск обновления по проекту: `site_id`, `job_run_id` (расход
LLM всего запуска пишется в одну строку журнала), `total`, `started_at`,
`finished_at`, `error_text`. Метка «теги обновлены …» у проекта — `finished_at`
последнего завершённого запуска.

**`wordstat_cache`** — ответы Wordstat по ключу (фраза, регион, вид запроса),
TTL 30 дней.

**`wordstat_calls`** — журнал обращений; по нему глобальный ограничитель считает
запросы за последний час по всем проектам.

**Настройки:** `wordstat_api_key` (секрет, Fernet — как `routerai_api_key`),
`wordstat_hourly_limit` = 100 (число), `meta_stoplist` — стоп-лист конкурентов и
мусорных фраз (леруа, лемана, петрович, авито, озон, «своими руками»…).

### Ход обновления проекта («Обновить метатеги»)

1. **Синхронизация дерева** из `catalog-categories` + сверка с sitemap:
   неопубликованные и без страницы → `skipped`; пропавшие с сайта → «удалена на
   сайте», из панели не стираются.
2. **Фразы и формы** — один вызов LLM (промпт `category_seeds`) на всё дерево:
   для каждой категории поисковая фраза и три формы. «Уголок металлический» →
   фраза «металлический уголок», формы «металлический уголок / купить
   металлический уголок / цена металлического уголка». Путь в дереве передаётся,
   чтобы LLM различала одноимённые подкатегории.
3. **Постановка в очередь — цепочкой.** Всем категориям с фразой ставится
   `queued`, в Celery уходит задача только ПЕРВОЙ из них; каждая задача по
   завершении ставит следующую `queued` категорию этого сайта. Так проект
   занимает не больше одного слота воркера: воркеров два (`--concurrency=2`), и
   77 задач разом встали бы в общую очередь перед партиями статей. Долгая задача
   на весь проект тоже отклонена — она держала бы слот часами.
4. **Задача категории**:
   1. резервирует у ограничителя столько запросов, сколько нет в кеше (до 3,
      см. ниже); если квоты на час нет — переставляет себя с `countdown` и
      отпускает воркер. `countdown` не больше 10 минут: у Redis-брокера
      `visibility_timeout` час, задача с ETA дольше него доставляется повторно.
      Проснувшись раньше, задача просто снова спрашивает ограничитель; время
      «продолжим ~в 15:05» хранится в `wait_until` категории;
   2. Wordstat: `topRequests` по фразе и региону проекта (`numPhrases` 300) и,
      если формы различаются, проверка склонения — два точных запроса; ответы —
      в кеш;
   3. решение о форме (ниже);
   4. LLM пишет теги (промпт `category_meta`);
   5. код валидирует; при нарушениях — один повтор с перечнем нарушений, потом
      `failed`;
   6. запись на сайт: есть метатег с этим url — PATCH пяти полей, нет — POST;
      `seo_text` не трогается; перед первой перезаписью старые значения — в
      `previous_json`.

**Перегенерация категории** — шаги 4.1–4.6 для одной категории; Wordstat
берётся из кеша, если данные моложе 30 дней, и квоту не тратит.

### Правила генерации

**Выбор формы — кодом, до LLM:**

- если `form_buy` без «купить» совпадает с `form_nominative` («купить
  профнастил»), проверка не нужна — на категорию 1 запрос;
- иначе два точных запроса, `totalCount` каждого: `"!купить !фанера"` и
  `"!купить !фанеру"` (у многословной фразы `!` ставится перед каждым словом) —
  на категорию 3 запроса. 77 категорий ≈ 230 запросов ≈ 2,5 часа при 100/час;
- частотнее несклонённая → `nominative`: название в начале, фраза строится
  корректно — «Фанера в Москве — купить по выгодной цене»;
- частотнее склонённая → `declined`: «Купить фанеру в Москве по выгодной цене»;
- обе частоты < 10 или равны → `declined` (грамотная форма).

LLM получает решение явной инструкцией и форму не выбирает.

**Контекст LLM:** название и путь категории, фраза и выбранная форма, город в
предложном падеже, бренд, топ-100 фраз Wordstat с частотами по городу,
`total_count`, `site_description` из карточки сайта — единственный разрешённый
источник фактов о магазине (доставка и т.п.).

**Правила полей (проверяет код):**

| Поле | Правило |
|---|---|
| title | ≤ 70 символов; оканчивается на « \| {brand}»; начинается с фразы в выбранной форме; содержит `city_in`; одно продающее слово — «купить» или «цена», что частотнее в выдаче |
| h1 | ≤ 60 символов; без бренда; фраза + город («Фанера в Москве»); не равен title без бренда |
| description | 140–170 символов; город и фраза; продающие слова из статистики; запрещены «в наличии», «скидки», «опт» и прочие утверждения, которых нет в `site_description` |
| keywords | ≤ 10 фраз через запятую, в нижнем регистре; каждая — фраза из выдачи Wordstat или «фраза + город»; сначала коммерческие, затем виды |
| ai_keywords | 10–15 фраз естественным языком, как спрашивают LLM: «где купить фанеру в Москве», «какая фанера подходит для пола» |

Во всех полях — ни одного слова из `meta_stoplist`.

**Низкий спрос:** `total_count` < 50 в месяц — теги генерируются по названию и
тому, что есть в выдаче; категория помечается «мало данных».

**Промпты** `category_seeds` и `category_meta` — в `PROMPT_KEYS` с объявленными
`PROMPT_VARIABLES`, сидятся дефолтами, редактируются в админке, переопределяются
на сайт — как существующие.

### Интерфейс

Пункт меню **«Метатеги категорий»**, `/category-meta`.

**Список проектов:**

- «Добавить проект» — выбор сайта из заведённых, город, бренд; регион Wordstat
  подставляется по городу, при неоднозначности — выбор из подсказок;
- строка проекта: сайт, город, «Теги обновлены 16.09.2026 14:20» или «ещё не
  обновлялись», кнопка **«Обновить метатеги»**;
- во время запуска вместо кнопки — «В работе: 12 из 70»; при упоре в квоту —
  «ждём квоту Wordstat, продолжим ~в 15:05». Опрос сервера — как на странице
  партии.

**Проект раскрывается в дерево категорий.** Строка: название, ссылка на
страницу, статус (в очереди / в работе / готово / ошибка / пропущена / мало
данных), дата обновления. Клик — карточка:

- пять тегов со счётчиками символов;
- сводка Wordstat: фраза, выбранная форма и частоты обеих форм, `total_count`;
- свёрнутое «было на сайте до нас» (`previous_json`);
- текст ошибки, если есть;
- кнопка **«Перегенерировать»**.

Запись в `changelog.ts`, вид `feature`.

### Сбои

- **Wordstat** — сеть, 429, 5xx: до 3 повторов с паузой, затем `failed`. 401/403:
  запуск останавливается, текст «ключ Wordstat отклонён — проверьте настройку
  wordstat_api_key».
- **Ограничитель** резервирует слоты под блокировкой в БД — два воркера вместе
  не превышают лимит.
- **Сайт** — PATCH повторять безопасно. POST вслепую не повторяется: `ReadTimeout`
  после отправки неотличим от «создано, ответ не дошёл». Перед повтором список
  метатегов перечитывается; если url уже есть — PATCH. Тот же приём, что
  `_guard_duplicate_url` у статей.
- **Зависшие**: `in_work` дольше 30 минут показывается как зависшая, доступна
  перегенерация (как в `directions/2026-09-12-batch-resilience-design.md`).
- **Оборванная цепочка** (сообщение Celery потеряно, воркер перезапущен):
  запуск считается устаревшим, если 2 часа нет ни работающей категории, ни
  категории, ждущей квоту (меньше нельзя: цепочка может честно стоять в очереди
  Celery за партией статей); тогда «Обновить метатеги» снова доступна, старый
  запуск закрывается с пометкой «прерван».
- **Запуск завершён**, когда все категории в `done` / `failed` / `skipped`.
  Повторный запуск во время работы — 409.
- **Расход LLM** — в `JobRun` / `LlmUsage`, как у статей.

### Тесты

TDD, pytest, HTTP подменяется:

- выбор формы: совпадающие формы (1 запрос), пороги, ничья;
- валидация полей: длины, город, бренд, ≤ 10 keywords, сверка keywords с
  выдачей, стоп-лист;
- url корневой и вложенной категории; отсев по sitemap;
- upsert метатега: PATCH vs POST, защита от дубля при повторе POST;
- ограничитель: граница 100/час, перенос задачи с верным `countdown`;
- TTL кеша; разбор ответов LLM; переходы статусов и завершение запуска.

**Живая проверка** — локальный стенд (скилл `running-local-panel`), одна
категория «Фанера» на stroybaza-moscow.ru с настоящим Wordstat. Запись на боевой
сайт — только после подтверждения владельца.

## Вне рамок

- Цена в тегах.
- Ручное редактирование тегов в панели.
- Фильтр-страницы каталога (`?tip-smesi=…`) — их ~860 только на одном сайте, при
  квоте 100/час это отдельная задача.
- `seo_text` категорий.
