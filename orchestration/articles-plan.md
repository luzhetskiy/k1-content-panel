# Инструкция: процесс «Статьи» (отдельно от «Строителей»)

## Принцип разделения

Процесс статей изолирован от процесса компаний-застройщиков: свои скрипты в
`execution/articles/`, свой регламент. Общее — доступы к сайтам (`.env`) и
общий загрузчик файлов `execution/filemanager.py`.

| | Строители | Статьи |
|---|---|---|
| Скрипты | `execution/step*_*.py` | `execution/articles/*.py` |
| Шаблон | `builders.html` | HTML-шаблон статьи (см. «Шаблон» ниже) |
| Публикация | `POST /api/v1/staticpages/` | `staticpages` (раздел `/blog/`) **или** `articles` |
| Загрузка файлов | `execution/filemanager.py` (общий) | `execution/filemanager.py` (общий) |

## Входные параметры (спрашивать, если не даны)

1. **Сайт** — базовый URL (токен из `.env` по домену).
2. **Кол-во статей** — N.
3. **Шаблон статьи** — нужен **только для первой статьи на данном сайте**
   (см. раздел «Шаблон»). Для последующих не спрашивается.
4. **Кто предлагает темы** — агент или пользователь. Если агент — предложенные
   темы сверяются с уже существующими на сайте (шаг 1) и согласуются.
5. **Куда публикуем** — `pages` (staticpages, раздел `/blog/`) или `articles`.
6. **Parent ID** — только для `pages` (например 25 = «Полезные статьи» на
   stroybaza-samara.ru).
7. **Кол-во картинок** — агент предлагает, исходя из шаблона (тизер + картинки
   в тексте). Пользователь подтверждает/меняет.
8. **Стиль контентных картинок** — базовый промт-стиль, к которому агент
   добавляет сюжет каждой картинки.
9. **Стиль тизера** — либо «как у существующих тизеров на этом сайте» (агент
   ориентируется на уже созданные), либо отдельный промт-стиль. **Свой для
   каждого сайта** — запрашивать, если не задан.
10. **Водяной знак** — файл/текст водяного знака, накладываемого на контентные
    картинки. **Свой для каждого сайта** — запрашивать, если не задан.

> Параметры 8–10 постоянны для сайта — стоит сохранять их (память/конфиг), чтобы
> при следующих статьях на том же сайте не спрашивать заново.

## Шаблон статьи

- **Первая статья на сайте:** пользователь даёт HTML-шаблон (например `article.html`).
  По нему собирается разметка.
- **Последующие статьи на том же сайте:** шаблон-файл больше не нужен. Ориентир —
  **уже опубликованная статья на этом сайте** (эталонная): агент запрашивает её
  через API (`GET /api/v1/staticpages/{id}/` или `/articles/{id}/`), берёт `text`/`body`
  и повторяет структуру и классы разметки. Эталонная статья всегда одна и та же
  для сайта — она и служит живым шаблоном.

## Шаг 1. Темы + проверка на дубли

Проверка идёт **по API того раздела, куда публикуем**:

- `pages` → `GET /api/v1/staticpages/` постранично. Список отдаёт `id, title, url`
  (title доступен сразу — дозапросы detail не нужны). `parent` в списке нет и фильтр
  `?parent=` игнорируется, поэтому раздел вычленяем по префиксу url (`/blog/`).
- `articles` → `GET /api/v1/articles/` постранично, собираем `title` + `slug`.

Предложенные темы сверяем с `title` существующих: нормализация (нижний регистр,
без стоп-слов) + пересечение ключевых слов; близкая тема помечается как дубль и
не предлагается. Итог — согласованный с пользователем список тем.

## Шаг 2. Написание статей

- Текст пишет агент локально (без внешних LLM-API), по промту: полезная статья
  2500–3000 символов, структура строго по шаблону (первая статья) или по эталонной
  опубликованной статье (последующие).
- Пути контентных картинок в HTML — `/media/uploads/article-img/{имя}.webp`
  (стандарт `filemanager.ARTICLE_IMG_DIR`). Имена по шаблону `article_{N}-{k}`
  (N — номер статьи в партии, k — номер картинки).

## Шаг 3. Генерация картинок — `execution/articles/gen_images.py`

- `POST https://routerai.ru/api/v1/images`, `Authorization: Bearer $ROUTERAI_API_KEY`.
  Модель по умолчанию `openai/gpt-image-2`.
- **Важно:** `aspect_ratio` модель игнорирует — отдаёт фиксированные размеры,
  нужные пропорции получаем кропом (Pillow). Ответ — `data[0].b64_json` → webp.
- **Тизер** генерируется **отдельно, по теме статьи** (сюжет отражает заголовок):
  - стиль тизера — по параметру 9 (как у существующих на сайте либо отдельный промт);
  - тизер водяным знаком **не** метится (это обложка).
- **Контентные картинки** генерируются по стилю (параметр 8), иллюстрируют смысл
  своего параграфа. На них **накладывается водяной знак** сайта (параметр 10)
  перед загрузкой.
- Локально складываются в `articles_batch_*/images/`.

## Шаг 4. Загрузка картинок на сайт — `execution/filemanager.py`

Метод рабочий: `POST /api/v1/filemanager/` (авторизация обычным `Token`, НЕ
`X-STROYKER-KEY`; перезапись файла по имени; путь предсказуем).

- **Контентные картинки** (с водяным знаком) → `filemanager.upload_file(...,
  upload_to=ARTICLE_IMG_DIR)` → лягут в `/media/uploads/article-img/…`, на эти же
  пути ссылается HTML.
- **Тизер** — отдельным механизмом, это ImageField страницы, путём-строкой не
  задаётся:
  - `pages`: `filemanager.upload_page_teaser(site, page_id, bytes, filename)` —
    multipart прямо в поле `teaser_image` (файл ложится в `/media/staticpages/images/`).
  - `articles`: multipart-поле `image` при создании записи.

## Шаг 5. Публикация — `execution/articles/publish_articles.py`

- `pages`: `POST /api/v1/staticpages/` — `title, url:/blog/{slug}/, text,
  published:false, parent, wide_view:true, use_editor:false, meta_*`.
- `articles`: `POST /api/v1/articles/` — `title, slug (≤50), teaser, body,
  label (≤60, обяз.), published:false, meta_*`, тизер через поле `image`.
- Всё создаётся черновиком (`published:false`), публикует менеджер вручную.
- После создания страницы (для `pages`) — прикрепить тизер шагом 4.

## Что уже реализовано

- `execution/filemanager.py` — общий загрузчик (контент + тизер), константы
  `ARTICLE_IMG_DIR` / `SERVICE_IMG_DIR`.
- `execution/articles/gen_images.py` — генерация картинок через RouterAI (кроп,
  webp, многопоточно). **Нужно дописать:** отдельная генерация тизера по теме и
  наложение водяного знака на контентные картинки.
- `execution/articles/publish_articles.py` — публикация черновиков в `pages`.
  **Нужно дописать:** прикрепление тизера, ветку `articles`.

## Осталось доделать

1. Тизер: генерация по теме статьи + выбор стиля (как существующие / свой промт).
2. Водяной знак на контентные картинки (свой для каждого сайта).
3. Ветка публикации `articles` (поля teaser/body/label, тизер через `image`).
4. Автоориентир на эталонную статью сайта вместо файла-шаблона со второй статьи.
5. Хранение per-site настроек (стиль тизера, стиль картинок, водяной знак).
