# План: справка, пауза партии статей, история загрузок строителей, ошибки в метатегах (2026-09-18)

Четыре независимые доработки, один деплой (api + worker + frontend), одна запись
в «Доработки» на каждую.

## 1. Кнопка «Справка» в разделах Статьи / Строители / Метатеги

- Компонент `HelpButton` (кнопка с иконкой `?` рядом с заголовком раздела) →
  `Modal` с текстом. Тексты — в одном файле `frontend/src/help.tsx`, по ключу
  раздела: при изменении логики правится только он.
- Правило поддержки: любая доработка, меняющая порядок работы раздела, в том же
  коммите правит справку (как `changelog.ts`). Фиксируется в памяти проекта.

### Черновик текстов

**Статьи**
1. «Новая партия» — выбираете сайт и число статей. Панель читает уже
   опубликованные статьи сайта и по описанию сайта предлагает темы, не
   повторяющие существующие (до минуты).
2. Согласование тем: правьте, удаляйте, добавляйте свои. «Запустить генерацию».
3. Статьи собираются по очереди: текст по образцу эталонной статьи сайта →
   картинки внутри текста (с водяным знаком сайта) → обложка (без знака) →
   черновик на сайте. Одновременно идут не больше двух партий, остальные ждут.
4. Черновики публикует менеджер вручную в админке сайта.
5. Если что-то не так: «Приостановить генерацию» — текущая статья доделывается,
   следующие не начинаются. «Дособрать партию» продолжает с того же места;
   опубликованные статьи не пересобираются и второй раз не оплачиваются.
   Упавшую статью можно повторить отдельно, у готовой — перегенерировать картинки.

**Строители**
1. «Загрузить выгрузку Яндекс.Карт» (xlsx) — компании попадают в общую базу.
   Уже известные (по адресу сайта) обновляются, новые добавляются. Строки без
   сайта пропускаются. Файлы загрузок хранятся — их можно скачать из истории.
2. «Новая партия» — сайт, регион и категория из выгрузки, название сферы для
   сайта, ID тизера (category/city/location из CMS сайта) и количество.
3. Отбор: компании этого региона и категории, которых ещё нет на этом сайте,
   по убыванию числа отзывов. Список можно поправить — убрать или добрать.
4. На каждую компанию: текст с её сайта → переписывается ИИ (контакты, адрес,
   координаты, рейтинг — только из выгрузки, ИИ их не меняет) → логотип →
   страница-черновик по шаблону сайта → карточка-тизер.
5. Публикует менеджер вручную. Упавшую компанию можно пересобрать отдельно.

**Метатеги категорий**
1. «Добавить проект» — сайт, город (по нему регион Wordstat), бренд.
2. «Обновить метатеги»: панель читает дерево категорий сайта (неопубликованные
   и без страницы пропускаются), ИИ предлагает 1–4 варианта названия товара.
3. По каждой категории Wordstat показывает, как товар ищут в городе: берётся
   самый частый вариант, если это тот же товар («ГКЛ» → «гипсокартон»,
   но «ПСБ» — не банк), и более частая форма («фанера» / «фанеру»).
4. ИИ пишет title, h1, description, keywords (до 10), ai_keywords по
   статистике; панель проверяет длины и правила, при нарушении — одна
   повторная попытка. Цены и непроверенных обещаний в тегах нет.
5. Теги сразу записываются на сайт, прежние сохраняются в карточке категории.
   Wordstat — 100 запросов в час, поэтому сайт на 70–80 категорий обновляется
   ~4 часа; повтор в течение 30 дней идёт из кеша. Любую категорию можно
   перегенерировать; править руками — в админке сайта.

## 2. «Приостановить генерацию» на странице партии статей

Оборвать статью посередине нельзя без потери уже оплаченной работы (текст,
картинки), поэтому пауза кооперативная — между статьями.

- Миграция: `article_batches.pause_requested_at` (nullable datetime).
- `POST /api/article-batches/{id}/pause`: только для `status == running`.
  - `queued`/`working` → ставит `pause_requested_at`; runtime_state → `pausing`.
  - `stuck` → сразу `_reset_stuck_batch` + `status = paused`.
  - повторный вызов при уже запрошенной паузе — 400.
- `run_batch_sync`: перед каждой статьёй перечитывает флаг; если стоит —
  `status = paused`, флаг сброшен, джоба закрыта `ok` с логом «приостановлено,
  готово N/M». Та же проверка при старте задачи (пауза, пока ждала в очереди).
- `run()` принимает `paused` (это и есть «Продолжить» / «Дособрать партию»),
  сбрасывает флаг.
- Фронт: кнопка «Приостановить генерацию» (Popconfirm) при `working`/`queued`;
  статус «Останавливается — доделываем текущую статью» при `pausing`; тег
  «Приостановлена» для `paused`; «Дособрать партию» доступна для `paused`.
  Статус `paused` — в `statuses.ts` и в списке партий.
- Повтор отдельной статьи в `paused`-партии разрешён (как в `done`/`failed`).

## 3. «Строители»: подсказка о загрузке + хранение файлов

- Миграция: `company_imports.new_count` (int, nullable — у старых загрузок
  неизвестно), `company_imports.stored_path` (str, "" — файла нет).
- `import_file`: считает новых (не было в пуле) и обновлённых; сохраняет
  исходный файл в `MEDIA_DIR/company-imports/{id}.xlsx` (в т.ч. упавшие — чтобы
  можно было посмотреть, что не так).
- API: `GET /api/company-imports` отдаёт `new_count`, `has_file`, `uploaded_by`;
  новый `GET /api/company-imports/summary` → `{total_candidates}`;
  `GET /api/company-imports/{id}/file` — скачивание (auth-cookie, обычная ссылка).
- Фронт: строка «Всего строителей в базе: 5 120. Последняя загрузка «файл.xlsx» —
  18.09.2026 14:20: новых 312, обновлено 4 771 (5 083 строки)» + ссылка
  «История загрузок» → модалка со списком загрузок (дата, файл, кто, строк,
  новых, статус/ошибка, «скачать»).
- Файлы, загруженные до доработки, не сохранялись — у них «скачать» нет.

## 4. «Метатеги»: число категорий с ошибками на свёрнутой строке сайта

- `ProjectOut.error_count` = категории `failed` + зависшие (`is_stuck`) —
  обе в дереве показаны красным.
- Фронт: в колонке «Сайт» под доменом — красный тег «Ошибок: N», только если N > 0.
