# Фикс: kombu 5.7.0 несовместим с закреплённым redis 5.2.1 (воркер в crashloop)

Дата: 2026-11-19. Ветка: `fix/kombu-redis-pin`. Срочный фикс после деплоя 44584c8.

## Инцидент

Деплой 44584c8 (error-конверт RouterAI) пересобрал backend-образ. celery 5.4.0
разрешает `kombu>=5.3.4,<6.0` — свежая kombu 5.7.0 (вышла между 22 октября и
19 ноября) резолвится легально, `pip check` молчит (её требование
`redis>=6.4.0` живёт в extra `kombu[redis]`, который не включён). Но redis-транспорт
kombu 5.7.0 на рантайме проверяет `redis.VERSION >= (6,1,0)` в `_get_client`:

- воркер: `VersionMismatch` на старте consumer → crashloop (RestartCount 33);
- api: `apply_async` бросает то же исключение ПОСЛЕ коммита статуса — партия 171
  осталась `running` без задачи (run_requested_at 11:13:54 UTC), статья —
  `generating` без задачи (retry-эндпоинт, тот же паттерн); очередь Redis пуста,
  JobRun не создавался, ничего не оплачено;
- панель честно показала «Похоже, задача зависла» (batch_runtime_state: job None,
  waiting > QUEUE_GRACE_SECONDS=600 → stuck).

Старый образ (4 недели) и dev-образ от 13 августа содержали kombu 5.6.2 — её порог
`redis>=3.2`, с redis 5.2.1 работает. Health-чек api после деплоя прошёл (api не
подключается к брокеру на старте) — проверка воркера после деплоя отсутствовала,
это урок: после деплоя смотреть логи воркера («ready») и RestartCount.

## Фикс

1. `kombu==5.6.2` явно в requirements.txt (комментарий: поднимать только вместе
   с celery и redis; celery[redis] 5.4.0 сам ограничивает redis<6.0, так что
   альтернатива «поднять redis до 6.x» требует и подъёма celery — отдельная задача).
2. Регресс-тест `tests/test_deps_compat.py`: создание канала kombu redis без живого
   Redis — VersionMismatch бросается до сети, сетевой отказ допустим. RED проверен
   в сломанном прод-образе (kombu 5.7.0): 1 failed за 0.43 с.
3. Запись в «Доработки» (frontend changelog.ts) — деплой включает frontend.

## Проверки

- RED в сломанном образе → GREEN в пересобранном dev-образе + полный регресс.
- После прод-деплоя: воркер «ready» в логах, RestartCount не растёт,
  `celery -A app.celery_app inspect ping` отвечает, тест совместимости зелёный
  в новом прод-образе.
- Партия 171: очередь пуста, задач нет → после фикса менеджер жмёт «Дособрать
  партию» (stuck → _reset_stuck_batch: generating→failed, published пропускаются,
  двойной оплаты нет).
